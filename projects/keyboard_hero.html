Keyboard Hero

Goal

I had 3 main goals that I had to accomplish in order to complete this project:

  1. Create a fast game engine without using libraries that abstract away large or important parts.
  2. Use the game engine to create a game similar to Guitar Hero.
  3. Create a custom controller to play the game.

Process

My process involved lots of testing and design. It took place in 3 main parts: Game Engine, Game, Controller.

Game Engine

Entity System

The first part of the game engine that I did was the entity system. The entity system is the system that you use to track entities in your game. An entity is anything that has state. This is difficult because it has to be very flexible and maintain performance because it is such a critical element of any game engine. I experimented with many different types of entity systems, but I found that an Entity Component System (ECS) was the most appealing to me due to it's flexibility.

Platform Abstraction

I had to abstract the operating system specific parts of the codebase so that in the future the engine could support multiple operating systems. I found that they easiest way to do this wasn't to create a library that was a wrapper around each operating system operation, but instead was to have the main running context be operating system specific and then the os-independent code be ran by the os-dependent code. I chose this way because many operating system operate differently, and this way doesn't enforce all oeprating systems to operate the same way.

Graphics

I chose to use the Vulkan API for graphics because of it's compatability with many different operating systems and OpenGL is technically deprecated. This presented a big issue because Vulkan is a massive API and is very complex. I had to write multiple test programs and make many different charts in order to learn how to properly use Vulkan.

App

I had to answer the question: what is the app to the engine? My answer was that it was a list of 3 functions: a start function, a run function, and an end function. This had the benefit of allowing me to implement hot-reloading by having the game be a run time linked library in debug builds.

Resources

Another problem that I had to solve was how would I load 3D objects, audio files, and fonts. I chose to create my own loader for .obj 3D model files, but fonts were too difficult, so I used a library called FreeType2. I was running out of time, so I used a 3rd party library to load sound files.

Game

Structure

I wanted to structure the game into modes. I chose to design the game so that each mode would have it's own file with it's own start, run, and stop functions that would be called based on what the current mode was.

Serialization

My game had to be able to create and store maps. For this I created my own library and file format to store the different levels inside the game.

Controller

Latches

I found the physical design troubling because I would have to make the keys able to rotate freely and be printable seperate from the base so that I can attach them. I came up with many different methods and over 10 prototypes, but I ended up using a simple solution that only allowed me to attach it when it is rotated upwards.

Software

The library for the board that I was using was only in Python. I had to learn how the python code works and recreate it inside C++ so that it would be compatible with my project written in C++.

Outcome

I successfully completed my goals with the only exception being that I used libraries for font and audio file processing. I learned a lot about how computers work because I had to optimize the code for performance. I also learned about how graphics rendering, and operating systems work due to me having to deal with them extensively. However, the most important skill that I learned from this is designing the structure of a program. Most of the mistakes I made were because my program structure didn't allow me to accomplish something. I had to constantly restructure my program until I found out a way that worked. Now whenever I go into a project I map out the program structure thoroughly.
